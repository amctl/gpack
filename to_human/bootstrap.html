gpack: research bootstrap

Deep dive into binary packers, similar implementations, and Goose programs · 22 Nov 2026

What is in this repository?

PRODUCT.md is a detailed proposed architecture. There is no gpack implementation or measured baseline yet. goose-bin/ bundles the Goose compiler, language docs, stdlib, sample programs, and graphics/physics packages.

Prior art points to an access-model choice

ZIP combines local headers and a trailing central directory. libarchive is deliberately stream-oriented and treats random access as a separate capability. Zstandard seekable frames add an index for independent decompression, with frame size trading ratio against range-read latency. Quake PAK is a compact payload-then-directory example. These are competing design points, not one universal format.

Goose-specific finding

Large result queues are the primary design risk. Goose threads exchange copied flat values. Queue limits count messages, not bytes. The bundled Mandelbrot worker sample sends tiny rows, so it demonstrates ordering but not large-chunk scalability. Current os.read_file reads the whole file; scalable streaming needs a native I/O boundary or a stdlib extension.

Recommendation

Before freezing a format or default chunk size, implement a small benchmark comparing whole-file frames, fixed chunks, and raw storage. Bound in-flight bytes explicitly. Specify deterministic metadata/path policy and safe extraction rules. Keep archive structs explicitly encoded rather than dumping Goose structs.
