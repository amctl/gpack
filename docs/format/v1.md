# gpack archive format v1

Status: normative design for the initial implementation. All integers are
unsigned little-endian unless stated otherwise. No Goose or C struct may be
written directly to disk; encode and decode each field explicitly.

## File layout

```text
64-byte header | payload region | entry index
```

The index occupies the final `index_size` bytes of the file. The header and
index are read and validated before payload allocation or decompression.

## Header (64 bytes)

| Offset | Width | Field | V1 value / meaning |
|---:|---:|---|---|
| 0 | 8 | magic | ASCII `GPKARCH` followed by NUL |
| 8 | 2 | major | `1` |
| 10 | 2 | minor | `0` |
| 12 | 4 | header size | `64` |
| 16 | 8 | entry count | `0..1,000,000` |
| 24 | 8 | index offset | absolute byte offset |
| 32 | 8 | index size | `4..64 MiB` |
| 40 | 4 | index CRC32 | IEEE CRC32 of the complete index bytes |
| 44 | 4 | header CRC32 | IEEE CRC32 of all 64 header bytes with this field zeroed |
| 48 | 16 | reserved | all zero |

For v1, `index_offset + index_size` must equal the archive file size and
`index_offset` must be at least 64. Unknown major/minor versions, nonzero
reserved bytes, invalid counts, arithmetic overflow, and CRC mismatches are
errors.

## Index records

The index begins with a 32-bit entry count, which must equal the header count.
Then it contains exactly that many records. Each record consists of this
40-byte prefix followed by `path_length` bytes of UTF-8 path data:

| Record offset | Width | Field | Meaning |
|---:|---:|---|---|
| 0 | 4 | path length | `1..4096` bytes |
| 4 | 1 | codec | `0` raw, `1` Zstandard |
| 5 | 3 | reserved | all zero |
| 8 | 8 | uncompressed size | `0..8 GiB` |
| 16 | 8 | payload offset | absolute offset in payload region |
| 24 | 8 | stored size | encoded bytes in payload region |
| 32 | 4 | content CRC32 | IEEE CRC32 of uncompressed asset bytes |
| 36 | 4 | reserved | zero |

Records are sorted by unsigned lexicographic path-byte order and paths are
unique. There are no trailing bytes after the last path. Nonempty payload
ranges must start at or after byte 64, end at or before `index_offset`, must
not overlap, and must not overflow when offset and stored size are added.
Nonempty ranges occur in record order, matching the canonical path order. A
zero-length asset uses codec `raw`, stored size zero, CRC32 zero, and an offset
between 64 and `index_offset` inclusive; it occupies no payload bytes.

## Payload codecs

Codec `0` stores source bytes verbatim; `stored_size` must equal
`uncompressed_size`. Codec `1` stores exactly one complete Zstandard frame,
encoded with Zstandard 1.5.7 at level 3, with frame content checksum enabled
and no dictionary. The frame must decode to exactly `uncompressed_size`, and
the frame's compressed extent must equal `stored_size`; concatenated frames and
trailing bytes are rejected. Writers select raw storage whenever the Zstandard
frame size is greater than or equal to the source size.

The per-entry content CRC32 is checked after decoding for both codecs. Zstandard
frame checksums are also verified by the decoder. Neither checksum is an
authenticity mechanism.

## Path bytes

Paths are valid UTF-8 relative identifiers using `/`. Writers convert host
directory separators to `/`, preserve Unicode code points and case, and sort
the resulting UTF-8 bytes. Reject NUL, backslash, leading `/`, empty
components, `.` and `..` components, invalid UTF-8, and duplicate path bytes.
Lookup is exact and case-sensitive. V1 does not extract archive paths onto a
filesystem.

## Read and validation requirements

Readers validate header and index CRCs, counts, versions, path bytes, record
sizes, codec IDs, reserved fields, raw/stored size relationships, and all
payload ranges before returning data. Enforce a 64 MiB maximum index, one
million entries, and 8 GiB maximum uncompressed size per format record. A
runtime may enforce a stricter allocation limit; v1 defaults to 32 MiB per
asset and four concurrent reads.

Writers emit entries in canonical path order and payloads in the same order.
Header/index encoding is explicit little-endian. All reserved bytes are zero.
The writer computes index CRC32 after serializing the complete index, then
header CRC32 with the header CRC field zeroed.
